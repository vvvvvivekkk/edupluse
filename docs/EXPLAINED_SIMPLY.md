# EduPulse explained simply

A plain-language guide for presenting and defending the project. No prior ML knowledge assumed.

## The one-sentence version

EduPulse looks at a student's marks and habits, guesses how much help they need, picks a kind of
help, checks whether it worked, and uses that result to pick better help next time.

## The loop, step by step (with the code that does each step)

1. **Records go in.** Quiz scores, attendance, assignment status and practice results are stored in
   PostgreSQL (a database: organised tables of data). → `routers/records.py`

2. **"How is this student doing?" — Random Forest.** A *classifier* is a program that sorts things
   into categories. A *decision tree* is a classifier built from yes/no questions ("is the average
   score below 55?"). A *Random Forest* is 300 slightly different trees that each vote; the majority
   wins. It outputs one of: Normal, Attention Needed, High Support Need, plus how confident it is
   (the percentages on screen). → `ml/state_model.py`

3. **"Which kinds of help make sense?" — eligibility rules.** Plain if/then rules written by people,
   not learned. Example: "low score on a topic AND weak practice accuracy → learning material or
   practice questions are allowed." This guarantees the system never suggests something
   inappropriate. → `engine/eligibility.py`

4. **"Which one of the allowed options?" — Thompson sampling.** This is a *bandit algorithm*. The
   name comes from slot machines ("one-armed bandits"): you have several machines and want to find
   the best one without wasting too many tries. Each type of help is an "arm."
   - For each arm the system keeps a belief: "practice questions usually give about +0.3, but I'm
     not very sure." Few observations = very unsure.
   - To choose, it draws a random guess from each belief and picks the highest guess.
   - Unsure arms sometimes produce high guesses, so they get tried (**exploration**). Arms that
     have worked well usually produce high guesses, so they get chosen often (**exploitation**).
   - *Linear* means the belief depends on the student's situation (score, attendance, state…), so
     it can learn "material works for weak-mastery students, practice works for the others."
   → `engine/thompson.py`

5. **Student does the activity**, then takes a **follow-up assessment** on the same topic.

6. **"Did it work?" — reward.**
   - *Learning gain* g = (after − before) / (100 − before). It measures improvement as a share of
     the room left to improve: going 40 → 70 is g = 30/60 = 0.5. If "before" was already 100 the
     formula would divide by zero, so that case is handled separately.
   - *Engagement change* e: did attendance/assignments/practice activity go up or down?
   - *Reward* r = 0.7 × g + 0.3 × e. Then: r ≥ 0.30 Positive, ≥ 0.05 Partial, otherwise No Improvement.
   → `engine/reward.py`

7. **"Learn from it" — policy update.** The chosen arm's belief is updated with this result (two
   running sums, called A and b). Each update is saved as a new *policy version*, so you can always
   see exactly what the system believed at any time. The same result can never be counted twice.
   → `engine/service.py: evaluate_response`

8. **Re-check the student.** The follow-up score is a new record, so the Random Forest runs again and
   the state may change (in the demo: High Support Need → Attention Needed). Then the loop repeats.

If a student shows No Improvement twice in a row, faculty support becomes allowed and the student is
flagged on the faculty dashboard.

## Questions you will probably be asked

**"Is the 71% accuracy real?"** It is measured honestly on data the model never saw during training,
but the data are synthetic (generated by a program), so it only proves the pipeline works, not that
it predicts real students.

**"Why not just use rules?"** Rules decide what is *allowed*. They can't learn which allowed option
actually works for which kind of student. Thompson sampling learns that from outcomes. In simulation
it had about half the regret of random choice and a third of a fixed rule.

**"What is regret?"** The gap between the best possible choice and the choice made, added up over time. Lower is better.

**"Why Random Forest and not something else?"** It was specified, and we checked: it beats a single
tree and a baseline clearly, and ties logistic regression. Ties are reported honestly in `DATA_AND_MODEL.md`.

**"How do you stop it giving inappropriate help?"** Thompson sampling only chooses among options the
rules allow; a test checks 500 selections and none are outside the allowed set.

**"Can the decision be explained later?"** Yes. Every selection stores the student's situation, the
allowed options, the random guesses for each option, the random seed and the policy version. The
faculty view shows all of it.

**"Does it replace teachers?"** No. It suggests and records; faculty see every student who needs
review and can record their own support.
