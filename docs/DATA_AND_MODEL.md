# Data and Model Documentation

> **All results in this document are synthetic-data evaluation.** They show that the pipeline
> trains and predicts correctly. They are not evidence of real-world predictive accuracy.

## 1. Dataset source and permissions

- **Source**: generated by `backend/app/ml/synthetic.py` (`generate_students(3000, seed=42)`).
- **Permissions**: no real student data is used, so no data-protection permissions are required.
- A suitable real labelled dataset was not available. Per brief §11.2 this limitation should be
  discussed with the project owner before any real deployment.

## 2. Data-generation rules

Each synthetic student has two hidden traits: `ability ~ N(0,1)` and `engagement` (correlation ≈ 0.4 with ability).
Observable features are noisy functions of these traits (all clipped to 0–100):

| Feature | Rule |
|---|---|
| previous_result_pct | 65 + 12·ability + N(0, 8) |
| avg_score | 62 + 14·ability + 4·engagement + N(0, 7) |
| latest_score | avg_score + N(0, 9) |
| attendance_pct | 82 + 9·engagement + N(0, 6) |
| assignment_completion_pct | 78 + 13·engagement + 3·ability + N(0, 9) |
| practice_accuracy_pct | 60 + 13·ability + 5·engagement + N(0, 10) |

Each optional feature is missing completely at random with probability 0.08 (latest_score is always present).

**Target label** comes from a separate hidden *end-of-term outcome* = 58 + 13·ability + 7·engagement + N(0, 7), which the model never sees:

| Label | Definition |
|---|---|
| normal | outcome ≥ 60 |
| attention_needed | 45 ≤ outcome < 60 |
| high_support_need | outcome < 45 |

This makes the task a genuine prediction under noise (inferring a future outcome from present
indicators), not re-discovery of the formula that produced the inputs. Even so, the model's
performance reflects these assumed rules only.

Class distribution: normal 1360, attention_needed 917, high_support_need 723.

The demo database (`scripts/seed.py`) uses 16 students from the same generator (seed 2026);
student1 is set to a clear "weak in Recursion" profile for the demonstration. **No intervention
history is pre-generated** — every intervention/response in the app comes from running the cycle.

## 3. Preprocessing

`Pipeline([SimpleImputer(strategy="median", add_indicator=True), RandomForestClassifier(...)])`.
Medians are learned on the training split only. No scaling is needed for trees.

## 4. Train / test split

Stratified hold-out: 2250 train / 750 test (75/25, `random_state=42`). The test set is used once, for final evaluation only.

## 5. Model-selection process

5-fold stratified cross-validation **on the training set only**, macro-F1:

| Model | CV macro-F1 (mean ± sd) |
|---|---|
| Random Forest (300 trees, depth ≤ 8, min leaf 5, balanced class weights) | 0.732 ± 0.021 |
| Logistic Regression (standardised, balanced) | 0.736 ± 0.023 |
| Decision Tree (depth ≤ 5) | 0.680 ± 0.014 |
| Majority-class baseline | 0.208 ± 0.000 |

## 6. Suitability of Random Forest

Random Forest clearly outperforms a single tree and the baseline, and is statistically tied with
Logistic Regression (difference 0.004, well within one SD). It is retained because (a) it is the
agreed model, (b) it performs as well as the best alternative, (c) it captures non-linear
interactions without manual feature engineering, which matters with real data, and (d) it
provides feature importances used in explanations. If the project owner prefers the simpler
linear model given equal performance, swapping is a one-line change in `ml/train.py`.

## 7. Evaluation on the held-out test set (Random Forest)

| Metric | Value |
|---|---|
| Accuracy | 0.715 |
| Precision (macro) | 0.716 |
| Recall (macro) | 0.710 |
| F1 (macro) | 0.710 |
| ROC-AUC (one-vs-rest, macro) | 0.880 |

Per class:

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| normal | 0.850 | 0.753 | 0.799 | 340 |
| attention_needed | 0.538 | 0.646 | 0.587 | 229 |
| high_support_need | 0.759 | 0.729 | 0.744 | 181 |

Confusion matrix (rows = true, columns = predicted):

| | normal | attention | high support |
|---|---|---|---|
| **normal** | 256 | 81 | 3 |
| **attention_needed** | 42 | 148 | 39 |
| **high_support_need** | 3 | 46 | 132 |

Observations: almost all errors are between adjacent categories (only 6 of 750 are
normal↔high-support). The middle class is hardest, as expected for an ordinal target with noise.
This is why the system treats the prediction as guidance and keeps faculty in the loop.

Feature importance: avg_score 0.29, practice_accuracy 0.22, latest_score 0.15,
previous_result 0.14, assignment_completion 0.11, attendance 0.08.

Full details are regenerated in `backend/models/model_card.json` by `python -m app.ml.train`.
