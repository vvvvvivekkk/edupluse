# EduPulse REST API

Base URL: `http://localhost:8000`. Interactive documentation (generated by FastAPI): **`/docs`** (Swagger UI) and **`/redoc`**. Machine-readable spec: `openapi.json` in this folder.

## Authentication

`POST /api/auth/login` with `{"email", "password"}` returns `{access_token, user}`. `email` may also be a student's roll number (username), e.g. `{"email": "EP26001", ...}`. Send `Authorization: Bearer <token>` on every other request. In Swagger, use **Authorize** (OAuth2 form at `/api/auth/token`).

## Authorisation rules

- Students: only their own student id. Faculty: only assigned students. Admin: all.
- Out-of-scope student → `403`. Missing/invalid token → `401`. Wrong role → `403`.

## Error responses

| Code | Meaning |
|---|---|
| 401 | not authenticated / token expired |
| 403 | role or student scope not permitted |
| 404 | not found |
| 409 | conflict: open intervention exists, already completed, duplicate response, already evaluated, record already exists, record locked because it is evidence for an intervention result |
| 413 | import file larger than 1 MB or more than 2000 rows |
| 422 | validation error: missing/out-of-range fields, incomparable measurements, missing required indicator |

Body: `{"detail": "human-readable message"}` (validation errors: list of field errors).

## Key request/response examples

### Select an intervention
```http
POST /api/interventions/select
{"student_id": 1}
```
```json
{"student_id":1,"state":"high_support_need","eligible":["targeted_material","targeted_practice","study_plan","faculty_support"],
 "selected":"targeted_practice","assignment_id":1,"policy_version":1,
 "explanation":["R1b: Low assessment performance, topic mastery not yet measured"],
 "sampled_scores":{"targeted_practice":{"sampled_score":0.756,"posterior_mean_score":0.0,"posterior_sd_score":0.968,"n_observations":0}, "...":"..."},
 "rng_seed":1234567,"context_vector":{"bias":1.0,"latest_score":0.375,"...":"..."}}
```

If no intervention is indicated (state Normal, no rule matched) `selected` and `assignment_id` are `null` with a `message`.

### Record a response (and evaluate)
```http
POST /api/interventions/1/response
{"post_score": 72, "evaluate": true}
```
```json
{"response_id":3,"evaluated":true,"evaluation":{"learning_gain":0.552,"engagement_change":0.0,"reward":0.386,
 "category":"positive","policy_update":{"from_version":1,"to_version":2,"arm":"targeted_practice","arm_observations":1},
 "state_reassessment":{"state":"attention_needed","model_version":"rf-synth-1.0"}}}
```

A second call returns `409` and does not change the policy. `POST /api/interventions/{id}/evaluate` evaluates a response recorded with `evaluate:false`.

### Academic record
```http
POST /api/academic-records
{"student_id":1,"record_type":"assessment_result","assessment_title":"Quiz 5","topic_id":5,"raw_score":14,"max_score":20}
```
`record_type` is one of `assessment_result`, `attendance`, `assignment`, `practice`; each requires its own fields (see Swagger).

### Bulk import (CSV)
```http
POST /api/academic-records/import?dry_run=true      (multipart/form-data, field "file")
```
```csv
roll_number,record_type,assessment_title,topic,raw_score,max_score,period_start,period_end,sessions_attended,sessions_total,assignment,status,questions_attempted,questions_correct
EP26001,assessment_result,Quiz 5: Object-Oriented Basics,Object-Oriented Basics,14,20,,,,,,,,
EP26001,attendance,,,,,2026-10-20,2026-10-26,4,5,,,,
EP26001,assignment,,,,,,,,,Assignment 5: Object-Oriented Basics,submitted,,
EP26001,practice,,Loops,,,,,,,,,10,7
```
```json
{"dry_run":true,"imported":0,"rows":4,"valid":4,"errors":[],"by_type":{"assessment_result":1,"attendance":1,"assignment":1,"practice":1},"students":1}
```
Each row is validated exactly like `POST /api/academic-records` plus authorisation (faculty: assigned students
only). With `dry_run=false` the import is all-or-nothing: if any row fails the response is `422` with one entry
per bad row (`{"loc":["row",5],"msg":"Row 5: raw_score cannot exceed max_score"}`) and nothing is stored. Row numbers
count the header as row 1. `topic`/`assignment` accept a name or an id; `student_id` may replace `roll_number`.

### Correct a record
```http
GET   /api/students/1/academic-records
PATCH /api/academic-records/assessment_result/12
{"raw_score": 17, "reason": "Marking error found on re-check"}
```
```json
{"record":{"record_type":"assessment_result","id":12,"raw_score":17,"max_score":20,"score_pct":85.0,"locked":false,"...":"..."},
 "state_reassessed":"attention_needed"}
```
Correctable fields: assessment `raw_score`; attendance `period_start`, `period_end`, `sessions_attended`,
`sessions_total`; assignment `status`; practice `questions_attempted`, `questions_correct`. `reason` is required.
Before/after values go to the audit log. Records with `"locked": true` (follow-up assessments, practice done inside
an intervention) return `409`: evaluated intervention results cannot be altered.

### Assign a role
```http
PATCH /api/admin/users/20
{"role": "student", "roll_number": "EP26500"}
```
A missing profile is created for the new role (`roll_number` required for students, optional `department` for
faculty); existing profiles are kept. Admins cannot remove their own admin role or deactivate themselves (`422`).
